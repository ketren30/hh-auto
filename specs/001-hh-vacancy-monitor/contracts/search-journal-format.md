# Формат Markdown-журнала поиска вакансий

Документ задаёт **человекочитаемый** артефакт для каждого сохранённого в приложении поиска (профиля фильтров). Содержимое генерируется и обновляется приложением **локально** (FR-011); формат версионируется здесь.

## Имя файла

Рекомендуемый шаблон экспорта: `hh-auto-search-<stableProfileId>.md` или `<краткое_имя_поиска>-<stableProfileId>.md`. Реализация может хранить текст журнала в `localStorage`/IndexedDB без записи на диск до явного «Сохранить / Экспорт».

## Структура документа

1. Заголовок первого уровня: человекочитаемое имя поиска (или «Поиск `<id>`»).
2. Необязательный блок метаданных (список): закреплённые фильтры (текст запроса, опыт, формат, регион, исключения) — для воспроизводимости.
3. Таблица вакансий в синтаксисе **GitHub Flavored Markdown**.

### Обязательные столбцы таблицы

| Столбец (заголовок) | Смысл |
|---------------------|--------|
| `vacancy_id` | Стабильный идентификатор вакансии с hh.ru |
| `title` | Название вакансии |
| `employer` | Работодатель (если доступно из API) |
| `url` | Публичная ссылка на вакансию на hh.ru |
| `first_seen_at` | ISO 8601 — первое появление вакансии в этом поиске по данным приложения |
| `applied` | `да` / `нет` — отправлен ли отклик из приложения (или зафиксирован иной явный исход в будущих версиях) |

### Необязательные столбцы (если поддерживаются реализацией)

| Столбец | Смысл |
|---------|--------|
| `last_seen_at` | Последнее наблюдение вакансии в выдаче |
| `applied_at` | Время зафиксированной успешной попытки отклика из приложения |

## Пример фрагмента

```markdown
# Python удалённо — Сочи

- Запрос: `Python`
- Опыт: от 3 лет
- Формат: удалённая работа
- Регион: Сочи (area id зафиксирован в приложении)
- Исключения: `1С`, `PHP`

| vacancy_id | title | employer | url | first_seen_at | applied |
|------------|-------|----------|-----|---------------|---------|
| 12345678 | Python-разработчик | ООО Пример | https://hh.ru/vacancy/12345678 | 2026-05-01T10:15:00Z | нет |
```

## Новизна вакансий

Понятие **«новая»** относительно предыдущего успешного опроса реализуется приложением сравнением множеств идентификаторов (как в FR-004 для подписок); журнал фиксирует **историю наблюдений** (`first_seen_at`) и **отклик** (`applied`). Столбец «новая в этом цикле» в файл может не записываться: достаточно UI и сравнения снимков; при необходимости экспорт может добавлять столбец `new_in_last_cycle` как снимок на момент генерации файла.
