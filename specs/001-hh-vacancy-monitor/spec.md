# Feature Specification: Мониторинг подписок hh.ru и черновики сопроводительных писем

**Feature Branch**: `001-hh-vacancy-monitor`  
**Created**: 2026-05-01  
**Status**: Draft  
**Input**: User description: приложение для работы с данными пользователя на hh.ru через официальные возможности доступа к сервису: вход под учётной записью, получение списка подписок на вакансии, периодический опрос подписок с интервалом n минут; при появлении новых вакансий — подготовка текста сопроводительного письма для каждой вакансии с учётом сохранённого резюме, вывод вакансий и писем на экран с возможностью редактирования текста письма, звуковое оповещение. Шаблон содержания письма задан пользователем (три абзаца, указание должности и источника информации о вакансии, мотивация и культура, навыки и благодарность).

## Clarifications

### Session 2026-05-01

- Q: Где хранятся токены/сеанс доступа к hh.ru, текст резюме и учётные параметры для генерации писем? → A: Только локально на устройстве пользователя; без хранения этих данных на сервере приложения разработчика (вариант A).
- Q: Какие подписки участвуют в мониторинге и периодическом опросе? → B: Только подписки, которые пользователь явно включил в приложении (остальные не опрашиваются).
- Q: Поведение опроса при неактивной вкладке (приложение открыто)? → A: Опрос продолжается по интервалу n, пока открыта вкладка/окно приложения, даже если вкладка не на переднем плане.
- Q: Отправка отклика на вакансию из приложения? → B: Приложение должно уметь отправлять отклик через официально доступные для приложения возможности hh.ru (вариант B).
- Q: Как устроена отправка откликов (одна за раз или пакетно)? → A: Отдельное явное действие и подтверждение на каждую вакансию; пакетная отправка по умолчанию не используется (вариант A).

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Вход и доступ к подпискам (Priority: P1)

Пользователь входит в свой аккаунт на стороне hh.ru через предусмотренный для приложения способ авторизации, сохраняет или подтверждает текст резюме для последующего использования при генерации писем, видит актуальный список своих подписок на вакансии (поиски/уведомления) с hh.ru и для каждой отмечает, участвует ли она в мониторинге; в опросе и поиске новых вакансий участвуют только явно включённые подписки.

**Why this priority**: без идентификации пользователя и получения подписок невозможно ни определение «новых» вакансий, ни персонализация писем.

**Independent Test**: можно проверить отдельным сценарием: успешный вход, отображение списка подписок и сохранённого резюме без включения опроса по расписанию.

**Acceptance Scenarios**:

1. **Given** пользователь не авторизован, **When** он завершает вход успешно, **Then** приложение показывает, что сессия активна, и позволяет перейти к подпискам.
2. **Given** авторизованный пользователь, **When** он открывает раздел подписок, **Then** отображается список подписок, полученный от hh.ru для этого пользователя.
3. **Given** отображённый список подписок, **When** пользователь включает мониторинг только для части подписок и сохраняет выбор, **Then** последующие опросы охватывают только эти подписки; выбор сохраняется локально до изменения.
4. **Given** пользователь вводит или обновляет текст резюме, **When** он сохраняет его, **Then** этот текст используется при следующих генерациях писем без повторного ввода.

### User Story 2 — Периодический опрос и обнаружение новых вакансий (Priority: P2)

Пользователь задаёт интервал опроса n в минутах. Пока открыта вкладка или окно приложения, приложение с этим интервалом продолжает запрашивать данные только по подпискам с включённым мониторингом — в том числе когда вкладка не активна (пользователь переключился на другую вкладку или приложение), и определяет вакансии, которые появились с последней успешной проверки и ещё не показывались пользователю в этом сеансе работы с приложением.

**Why this priority**: это ядро ценности «не пропустить новые предложения».

**Independent Test**: при тестовых данных или имитации появления новой записи можно проверить, что новая вакансия попадает в очередь показа и не дублируется при повторном опросе.

**Acceptance Scenarios**:

1. **Given** задан интервал n минут, активна фоновая проверка и есть хотя бы одна подписка с включённым мониторингом, **When** проходит n минут без ошибок доступа, **Then** выполняется очередной запрос только по таким подпискам.
2. **Given** результаты очередного запроса, **When** среди них есть вакансии, отсутствовавшие при предыдущем успешном запросе, **Then** они помечаются как новые для отображения и генерации писем.
3. **Given** запрос к hh.ru завершился ошибкой или недоступностью, **When** пользователь смотрит состояние приложения, **Then** видно понятное сообщение о сбое и при необходимости время следующей попытки без потери уже показанных данных.
4. **Given** активен мониторинг и вкладка приложения открыта, но не на переднем плане, **When** наступает очередной срок опроса по расписанию, **Then** приложение по-прежнему инициирует опрос включённых подписок (без требования вернуться на вкладку только для «пробуждения» таймера).

### User Story 3 — Черновики писем, экран и звук (Priority: P3)

Для каждой новой вакансии приложение формирует черновик сопроводительного письма по заданной пользователем структуре и содержанию (см. раздел требований к тексту), используя сохранённое резюме и сведения о вакансии. На экране пользователь видит вакансию рядом с редактируемым полем текста письма (может изменить черновик перед использованием). Пользователь может инициировать отправку отклика на hh.ru из приложения способом, разрешённым правилами доступа hh.ru для этого приложения: для каждой вакансии это отдельное действие с отдельным подтверждением (без пакетной отправки по нескольким вакансиям одним шагом). Пользователь видит результат каждой такой попытки. При появлении новых вакансий воспроизводится заметный звуковой сигнал.

**Why this priority**: ускоряет отклики и снижает ручную работу, но опирается на P1 и P2.

**Independent Test**: подставить фиксированные резюме и описание вакансии и проверить структуру черновика, редактирование, срабатывание звука при событии «новые вакансии», а также сценарий подтверждённой отправки отклика и отображение ответа hh.ru (или понятной ошибки).

**Acceptance Scenarios**:

1. **Given** новая вакансия и сохранённое резюме, **When** приложение завершает генерацию черновика, **Then** текст содержит три абзаца и отражает название должности, указанное во вакансии, источник информации о вакансии (как задано правилами шаблона), мотивацию и соответствие культуре, релевантные навыки и опыт из резюме, завершение благодарностью рекрутеру, в профессиональном тоне.
2. **Given** список новых вакансий с черновиками, **When** пользователь открывает экран, **Then** каждая вакансия отображается с отдельным редактируемым текстовым полем для письма.
3. **Given** хотя бы одна новая вакансия обнаружена в цикле опроса, **When** результаты доставлены пользователю, **Then** воспроизводится звуковой сигнал (если звук не отключён пользователем в настройках приложения).
4. **Given** пользователь отредактировал текст письма для вакансии и активна авторизация hh.ru, **When** он подтверждает отправку отклика через действие в приложении, **Then** приложение выполняет попытку отклика через официально допустимые для приложения средства hh.ru и показывает пользователю однозначный исход (успешная регистрация отклика, отказ с причиной по данным hh.ru, или необходимость дополнительных шагов на стороне hh.ru).
5. **Given** hh.ru сообщает, что отклик по этой вакансии уже отправлен или вакансия недоступна для отклика, **When** пользователь инициирует отправку, **Then** приложение не сообщает об успехе и показывает понятное состояние без создания дубликата отклика без явного намерения пользователя (если платформа допускает повторную попытку — только после явного подтверждения).
6. **Given** на экране несколько новых вакансий, **When** пользователь отправляет отклик, **Then** подтверждение и отправка относятся только к одной выбранной им вакансии; для следующей вакансии требуется новое явное действие и подтверждение.

---

### Edge Cases

- Пользователь не имеет ни одной подписки — показывается пустое состояние и инструкция, как это изменить на стороне hh.ru.
- Подписки есть на hh.ru, но ни одна не включена для мониторинга в приложении — опрос не выполняется (или не ставится в очередь); показывается понятное состояние с призывом включить хотя бы одну подписку; звуковые оповещения о новых вакансиях не генерируются из опроса.
- Истечение или отзыв авторизации — приложение запрашивает повторный вход и не создаёт ложных «новых» вакансий из кэша без свежего запроса.
- Очистка локальных данных приложения пользователем или смена устройства — повторная авторизация и повторное сохранение резюме; восстановление состояния только из локального хранилища или заново с hh.ru, без сервера приложения разработчика.
- Генерация письма недоступна (сервис недоступен, лимиты) — для вакансии показывается понятная ошибка и пустое или частично заполненное поле с возможностью ручного ввода.
- Отправка отклика отклонена hh.ru (лимиты, закрыта вакансия, несовместимость резюме, необходимость ответить на вопросы работодателя и т.п.) — пользователь видит сообщение, соответствующее ответу платформы; черновик письма сохраняется для правки или ручного продолжения на hh.ru при необходимости.
- Несколько новых вакансий за один цикл — звук срабатывает один раз за цикл уведомления; все вакансии перечислены с отдельными полями писем; отправка отклика возможна только по одной вакансии за подтверждение (без массовой отправки одним действием).
- Очень длинные описания вакансии или резюме — генерация использует релевантные части без поломки интерфейса; при необходимости пользователь сокращает текст вручную в поле письма.
- Пользователь ставит n ниже разумного минимума — приложение применяет минимальный допустимый интервал и сообщает об этом (чтобы снизить риск блокировок и перегрузки).
- Вкладка приложения открыта, но долго неактивна — опрос всё равно планируется (согласно уточнению A); фактический интервал между успешными опросами может отличаться от n из‑за дросселирования таймеров в браузере или политик ОС; в интерфейсе или справке допускается краткая подсказка пользователю об этом.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Приложение MUST позволять пользователю пройти авторизацию в соответствии с правилами доступа hh.ru и поддерживать сеанс до его окончания или выхода пользователя.
- **FR-002**: Приложение MUST загружать и отображать список подписок пользователя на вакансии (данные, которые hh.ru предоставляет авторизованному пользователю для этих подписок).
- **FR-003**: Пользователь MUST иметь возможность задать интервал опроса n (в минутах); приложение MUST опрашивать только подписки с включённым в приложении мониторингом, с этим интервалом и не чаще допустимого минимума, объявленного в настройках приложения.
- **FR-004**: Приложение MUST сравнивать результаты очередного опроса с предыдущим успешным по каждой включённой в мониторинге подписке и определять множество новых вакансий для пользователя в рамках текущего использования приложения.
- **FR-005**: Для каждой новой вакансии приложение MUST формировать черновик сопроводительного письма с использованием сохранённого текста резюме пользователя и текста/сведений о вакансии, доступных приложению.
- **FR-006**: Черновик письма MUST соответствовать следующей содержательной структуре (точная формулировка может варьироваться, структура — нет): первый абзац — должность, на которую претендует пользователь, и откуда пользователь узнал о вакансии; второй абзац — мотивация и заинтересованность, соответствие корпоративной культуре; третий абзац — навыки, опыт или достижения, релевантные работе, и благодарность рекрутеру за время; тон — профессиональный, ориентир — лучшие практики отрасли.
- **FR-007**: Экран новых вакансий MUST показывать для каждой вакансии редактируемое текстовое поле с черновиком письма; изменения пользователя сохраняются в этом поле до явной смены данных или очистки пользователем.
- **FR-008**: При появлении новых вакансий в результате опроса приложение MUST подать звуковой сигнал, если пользователь не отключил звуковые уведомления.
- **FR-009**: Пользователь MUST иметь возможность хранить и при необходимости обновлять текст резюме в приложении для участия в генерации писем.
- **FR-010**: При ошибках сети или отказах служб hh.ru приложение MUST показывать понятное сообщение и не сообщать о «новых» вакансиях на основе неподтверждённых данных.
- **FR-011**: Учётные данные сеанса hh.ru, сохранённый текст резюме и параметры доступа к генерации писем (если задаются пользователем) MUST храниться только локально на устройстве пользователя; приложение MUST NOT передавать их для постоянного хранения на управляемый разработчиком сервер приложения. Передача содержимого резюме и вакансии провайдеру генерации текста допускается только для получения черновика в рамках действия пользователя и политики этого провайдера.
- **FR-012**: Для каждой подписки из списка hh.ru пользователь MUST иметь возможность включить или выключить участие в мониторинге; приложение MUST учитывать при опросе и обнаружении новых вакансий только подписки с включённым мониторингом. Этот выбор MUST сохраняться локально до изменения пользователем.
- **FR-013**: Пока вкладка или окно приложения открыто и мониторинг активен, приложение MUST продолжать планировать опросы по интервалу n даже когда вкладка не на переднем плане; при закрытии вкладки/окна приложения циклический опрос прекращается до следующего открытия.
- **FR-014**: Пользователь MUST иметь возможность после редактирования текста письма инициировать отправку отклика на одну выбранную вакансию через официально доступные приложению возможности hh.ru; непосредственно перед отправкой MUST отображаться явное подтверждение действия пользователем. Одно подтверждение MUST соответствовать ровно одной вакансии; приложение MUST NOT отправлять отклики по нескольким вакансиям по одному общему подтверждению.
- **FR-015**: После попытки отправки отклика приложение MUST показать пользователю однозначный исход (успешная регистрация отклика; отказ с объяснением из ответа hh.ru; либо указание, что требуются дополнительные действия на стороне hh.ru). Приложение MUST NOT сообщать об успешном отклике при получении от hh.ru сигнала об ошибке или незавершённой операции.

### Key Entities *(include if feature involves data)*

- **Пользователь**: учётная запись hh.ru в контексте приложения; связан с сеансом и локально сохранёнными настройками (интервал опроса, звук) и локально хранимым резюме; без централизованного хранилища секретов у разработчика приложения.
- **Подписка на вакансии**: сохранённый пользователем на hh.ru поиск/уведомление, по которому приложение получает список подходящих вакансий; в приложении имеет локальный признак «мониторинг включён», определяющий участие в опросе.
- **Вакансия (элемент выдачи)**: должность, организация (если доступно), идентификатор и текст описания в объёме, предоставляемом API; используется для отображения и для генерации письма.
- **Черновик письма**: текст сопроводительного письма для конкретной вакансии, изначально сформированный автоматически, затем возможно изменённый пользователем в поле редактирования.
- **Попытка отклика**: действие пользователя по отправке сопроводительного текста на конкретную вакансию через hh.ru в рамках правил доступа; имеет зафиксированный исход (успех, отказ, необходимость дополнительных шагов), отображаемый пользователю.
- **Снимок опроса**: результат последнего успешного запроса для сравнения и выявления новизны.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Авторизованный пользователь может открыть список своих подписок не более чем за две минуты после успешного входа при стабильном интернет-соединении.
- **SC-002**: При интервале n, заданном пользователем в допустимых пределах, опрос выполняется с отклонением не более ±15% от n минут между успешными циклами в типичных условиях при активной вкладке; при длительной работе в фоновой неактивной вкладке допускаются дополнительные отклонения из‑за ограничений браузера и ОС (без требования жёсткой точности в таких условиях).
- **SC-003**: Не менее 90% автоматически сгенерированных черновиков при приёмочной проверке содержат ровно три смысловых абзаца и включают все обязательные темы из FR-006 (должность и источник; мотивация и культура; навыки/опыт и благодарность).
- **SC-004**: После обнаружения новых вакансий пользователь видит их список с полями для писем не позднее чем через 30 секунд после завершения генерации черновиков для всех новых позиций в этом цикле (при доступности службы генерации).
- **SC-005**: Звуковой сигнал воспроизводится в течение 2 секунд с момента готовности экрана/уведомления о новых вакансиях, если звук включён.
- **SC-006**: Не менее 80% пользователей в пробном использовании сообщают, что черновики сокращают время подготовки отклика по сравнению с написанием с нуля (опрос или короткая обратная связь после недели использования).
- **SC-007**: После того как пользователь подтвердил отправку отклика, итог попытки (успех, отказ или необходимость дополнительных шагов) отображается не позднее чем через 20 секунд при типичной доступности hh.ru и приложения.

## Assumptions

- Используются официально доступные пользователю и приложению механизмы hh.ru для авторизации и получения данных подписок и вакансий; объём полей вакансии определяется возможностями этих механизмов; отправка отклика выполняется только в рамках тех же официальных возможностей и ограничений hh.ru (включая требования к резюме, анкетам и лимитам).
- Секреты и персональный текст резюме не покидают контур «устройство пользователя» для целей хранения у разработчика приложения; синхронизация между устройствами через сервер разработчика не входит в объём.
- Генерация текста письма выполняется подключаемым интеллектуальным помощником (внешним или локальным), ключи и лимиты которого задаёт и хранит пользователь локально; приложение отвечает за подстановку резюме, текста вакансии и соблюдение описанной структуры письма при отправке запроса провайдеру генерации.
- Минимальный интервал опроса по умолчанию не ниже 3 минут, если пользователь не изменил политику и если это согласуется с ограничениями hh.ru (конкретное значение задаётся на этапе проектирования с учётом документации).
- Источник «откуда узнал о вакансии» в первом абзаце формулируется как типичный для контекста hh.ru (например, «нашёл вакансию на hh.ru в подписке [название подписки]»), если пользователь не задал иное правило в настройках.
- Мобильные браузеры и офлайн-режим не входят в минимальный объём, если не оговорено отдельно; приложение рассчитано на использование с активным соединением.
- Набор подписок с включённым мониторингом хранится только локально и не синхронизируется между устройствами через сервер разработчика.
- Опрос не ставится на паузу только из‑за того, что вкладка приложения неактивна; при этом точность таймеров в фоновой вкладке ограничивается возможностями среды выполнения (браузер, ОС).
- Отправка откликов осознанно по одной вакансии за раз: интерфейс не предлагает одну кнопку для массового отклика по всем новым позициям.
